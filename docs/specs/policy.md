# ポリシー 機能仕様書

## 1. 概要

### 1.1. 目的

本機能は、プロジェクト内の各サービスおよびアクションに対するアクセス許可を定義・管理するための機能を提供する.

ポリシーをエージェントに割り当てることで、外部システムからのアクセスに対して、許可されたサービスおよびアクションのみへのアクセスを可能にする.

### 1.2. 機能概要

ポリシーは、アクセスを許可するサービスおよびアクションの組み合わせを定義するものである.

本機能では、ポリシーの作成・取得・更新・削除・一覧取得を行う.

作成したポリシーはエージェントに割り当てることができ、割り当てられたポリシーに基づいてアクセス権限サービスが認可判定を行う.

なお、ポリシー単体ではアクセス主体を識別せず、エージェントへの割り当てによって認可判定に使用される.

### 1.3. 除外項目

以下は本機能の対象外とする.

- ポリシーとエージェントの割り当て管理

## 2. 機能仕様

### 2.1. ポリシーの作成

新しいポリシーを作成する.

ポリシーには、許可するサービスおよびアクションの組み合わせを定義する.

例として、ストレージサービスに対してエントリーの作成および取得を許可する場合、以下のように定義する.

| サービス | アクション |
| ----- | ----- |
| storage | createEntry |
| storage | getEntry |

作成時には、以下の条件を満たす必要がある.

ポリシーのIDは、ポリシー作成時にサーバー側で一意に生成する. IDはアクセス権限サービス内で一意とし、作成後の変更を禁止する.

- 許可するサービス・アクションの組み合わせが1つ以上定義されていること
- サービスおよびアクションの組み合わせに重複がないこと
- 指定されたサービスがプロジェクトに存在し、各サービスに属する指定されたアクションが存在すること

### 2.2. ポリシーの取得

指定されたポリシーを取得する.

取得対象のポリシーが存在しない場合、取得処理を失敗とする.

### 2.3. ポリシーの更新

既存のポリシーを更新する.

更新時には、以下の条件を満たす必要がある.

- 更新対象のポリシーが存在すること
- 更新内容には作成時と同様の入力条件を適用する
- IDは更新されないこと

更新時には、許可するサービスおよびアクションの組み合わせをすべて指定し、既存の定義を指定された内容に置き換える.

ポリシーの更新処理が正常に完了した後に開始される認可判定には、更新後のポリシー情報を使用する.

### 2.4. ポリシーの削除

既存のポリシーを削除する.

削除対象のポリシーが存在しない場合、削除処理を失敗とする.

ポリシーの削除が完了した時点で、当該ポリシーに関連付けられているエージェントとの割り当て情報をすべて削除する。

ポリシーの削除処理が正常に完了した後に開始される認可判定には、削除後のポリシー情報を使用する.

### 2.5. ポリシーの一覧取得

登録されているポリシーの一覧を取得する.

ポリシーが存在しない場合も取得処理は失敗としない. ポリシーが存在しない場合は、空の一覧を返却する.

## 3. 非機能要件

### 3.1. 応答性能

ポリシーに関する各操作の応答時間は、リクエストの受信からレスポンスの返却までのAPIサーバー内部の処理時間とし、通常時において以下を満たすこと.

- ポリシーの作成・取得・更新・削除：500ms以内
- ポリシーの一覧取得：1,000ms以内

> [!NOTE]
> ポリシーの削除においては、関連するエージェントへの割り当ての無効化を含めて500ms以内とする.

### 3.2. セキュリティ

以下のセキュリティ要件を満たすこと.

- ポリシーの管理操作は、認可されたアカウント・エージェントのみが実行できること
- 不正なサービスおよびアクションの組み合わせを登録できないこと
- ポリシーの情報を不正に取得・変更・削除できないこと

## 4. 運用要件

以下の運用要件を満たすこと.

- ポリシーの変更が以降の認可判定に反映されること
- ポリシーの削除が以降の認可判定に反映されること
- ポリシーの変更によって、既存のトークンを再発行する必要がないこと

> [!NOTE]
> トークンにはポリシーの定義を含めず、認可判定時にエージェントに割り当てられた最新のポリシー情報を参照する. これにより、ポリシーの変更および削除を既存のトークンに対しても反映できるものとする.
